## 一、分层与依赖方向（最重要，先看这段）

```
   main.cpp / Application        ← 主循环：调度 Update、收集命令、提交给后端
        │
        ├── Scene/               ← 场景数据：谁在哪里、用什么材质
        │
        ├── Camera               ← 摄像机：产出 View / Projection
        │
        └── Render/              ← 渲染核心（与图形 API 无关）：命令、队列、后端接口
                │
                └── Render/OpenGL/   ← 具体 API 实现：唯一认识 gl* / glfw* 的地方
```

**依赖方向只有一条：上层 → 下层，绝不反向。**

| 规则 | 说明 |
|---|---|
| ① 只有 `Render/OpenGL/` 里可以出现 `gl*` / `glfw*` | 其它层一律不碰图形 API |
| ② Camera 不知道窗口，也不知道渲染后端 | `aspect` 由上层喂进来，见第三节 |
| ③ Renderer 不知道 Camera / Scene | 它只接收「一份帧数据 + 一串命令」 |
| ④ 接口 `IRenderer` 里不放数据成员 | 只放纯虚函数；队列属于实现细节 |

> 判断一个设计对不对，问一句: **"如果明天换成 DirectX 后端，哪个文件要改？"**
> 答案应该只有 `Render/OpenGL/` 那一层。

## 二、矩阵归属（回答"矩阵该放在哪"）

| 矩阵 | 由谁计算 | 存在哪 | 怎么到 GPU |
|---|---|---|---|
| **Model** | `Transform`（位置/旋转/缩放） | `RenderCommand.transform` | `ExecuteRenderCommands` 里现算 |
| **View** | `Camera::Update()` | `Camera::ViewMatrix` | 每帧 `BeginFrame` 交给后端 |
| **Projection** | `Camera::Update()`，`aspect` 由上层传入 | `Camera::ProjectionMatrix` | 同上 |

**关键结论:**

- 相机**两个矩阵都要有**，但**不要自己去问窗口大小** —— 让逻辑层反向依赖渲染后端是错的。
- 窗口大小的**唯一真相源在渲染后端**（只有它知道 framebuffer 尺寸）。
- 上层每帧做一次转发:

```cpp
glm::vec2 size = renderer->GetViewportSize();   // 后端提供
camera.SetAspect(size.x / size.y);              // 相机只接收结果
camera.Update();
```

- **Renderer 里不要存 view/projection 的语义**，它只存"这一帧传进来的那一份"。
- `RenderCommand` 里**只存 `Transform`，不要再塞一个 mat4** —— 否则同一个 model 有两个真相源。

## 三、主循环顺序

```
Init:
    renderer->Init()                     // 建窗口 + 上下文 + GLAD
    加载 shader / mesh
    camera.SetAspect(renderer->GetViewportSize())

每帧:
    1. renderer->PollEvents()            // 先处理输入（回调会写 camera 的鼠标状态）
    2. camera.Update()                   // 逻辑更新: Yaw/Pitch/Radius → View/Projection
    3. 收集渲染命令                        // 遍历场景 → PushRenderCommand
    4. renderer->BeginFrame(frameData)    // 提交本帧的 view/projection/光源
    5. renderer->ExecuteRenderCommands()  // 排序 + 逐条绘制
    6. renderer->SwapBuffers()
```

**为什么顺序是这样:**

- `PollEvents` 必须在 `Update` **之前** —— 鼠标回调是它触发的，反了相机就晚一帧。
- `Update` 属于**逻辑层**，只改数据，**不做任何 GL 调用**。
- 每帧一次的相机数据（view/projection/光源）走 `BeginFrame`，
  每个物体一次的数据（model）走 `PushRenderCommand`。这就是"每帧一次 / 每物体一次"的区分。

## 四、接口草图

```cpp
// Render/RenderCommand.h
struct Transform { glm::vec3 position; glm::vec3 scale; glm::vec3 rotation; };

struct RenderCommand {
    Mesh*     mesh;
    Shader*   shader;
    Transform transform;          // 只存 Transform，model 矩阵在执行时算
};

// Render/Renderer.h
struct FrameData {
    glm::mat4 view;
    glm::mat4 projection;
    glm::vec3 lightPos;
    glm::vec3 lightColor;
};

class IRenderer {
public:
    virtual ~IRenderer() = default;

    // 生命周期 / 窗口
    virtual bool Init() = 0;
    virtual bool WindowShouldClose() = 0;
    virtual void PollEvents() = 0;
    virtual void SwapBuffers() = 0;
    virtual glm::vec2 GetViewportSize() = 0;   // 窗口尺寸交给上层，不直接给 Camera

    // 每帧
    virtual void BeginFrame(const FrameData& frame) = 0;
    virtual void SetClearColor(const glm::vec4& color) = 0;
    virtual void Clear() = 0;

    // 渲染命令
    virtual void PushRenderCommand(const RenderCommand& cmd) = 0;
    virtual void ExecuteRenderCommands() = 0;
};
```

注意 `IRenderer` 里**没有任何数据成员**。渲染队列是 `OpenGLRenderer` 的 `private` 成员；
等 Scene 层做出来之后，队列应该上移到场景层（收集 + 排序），后端只负责执行。

**待决策: Camera 放哪里？**
